# FRONTEND — Vue 3.5 + Inertia v3 + PrimeVue 5

> File placement and layers → `frontend/SKILL-ARCHITECTURE.md`.
> Security → `owasp/SKILL.md`.

**Stack (verified 2026-09-28):** Vue **3.5.43** (floor) · Inertia **3.7.1** (client) / 3.4.0 (server) ·
TypeScript **6.0.3** strict · Tailwind **4.3.3** + `tailwindcss-primeui` · PrimeVue **5.0.1** unstyled +
Volt **50** components in `src/volt/` · Pinia **4.0.3** + Colada **1.4.6** · `@primevue/forms` 5.0.1 +
Zod **4.6.5** · FullCalendar **7.1.0** · `motion-v` **2.5.0** · Vite **8.3.1** · Inter via Bunny Fonts.

> **Vue version policy.** 3.5 is the floor and 3.5 APIs are mandatory. Vue **3.6 is still a release
> candidate** (as of 2026-09-28) — do not pin an exact `-rc.N` string in rules, they move weekly.
> 3.6 is not a small release: reactivity is rebuilt on **alien-signals** and it ships **Vapor Mode**
> (direct DOM, no virtual DOM) as an opt-in per component. Until 3.6 is stable, do not adopt it, and
> when it lands re-verify the 3.5 API rules here before assuming they still hold.

> **`volt-vue` is an alpha CLI (`0.0.0-alpha.4`) and the whole UI layer is generated by it.** Treat
> `src/volt/` as code-ownership with an upstream that can change shape between releases: check
> `git diff` after every `volt-vue add`, and never hardcode the component count.

## 0. Token-first styling

Never hardcode a colour. No hex, no `bg-red-600`, no `bg-[#1b1b18]`. Either a semantic token from
`globals.css` or a PrimeUI bridge class (`bg-primary`, `text-surface-700`, `border-primary-200`).

**`resources/css/app.css` must contain, in this order:**

```css
@import 'tailwindcss';
@import 'tailwindcss-primeui'; /* REQUIRED by Volt */
@import './globals.css';
@custom-variant dark (&:is(.dark *));
```

`@source` must cover `../**/*.vue` **and** `../../src/**/*.vue` — Volt lives in `src/`, and without
that directive Tailwind never sees the Volt classes and `bg-primary` is silently dropped from the build.

`globals.css` holds the `--p-primary-*` / `--p-surface-*` palette, the semantic token layer, the dark
overrides, and the `tabular-nums` utility (Inter's `tnum` feature — use it on DataTable numeric cells so
digits align down a column).

## 1. Dark mode

The `.dark` class on `<html>`, and nothing else. No `data-theme`, no `.light`. Toggle it with
`useColorMode` from `@vueuse/core`; that store is the only source of persistence. Inline the toggle
script in the `app.blade.php` `<head>` to avoid a flash of the wrong theme.

## 2. Accessibility — WCAG 2.2 AA

Every interactive element reachable by keyboard, with a visible focus ring that is never removed.
Every image has alt text. Every form field has a `<label for>`. Every icon-only control has
`aria-label`. Dialogs trap focus and restore it on close. Colour contrast ≥ 4.5:1 for body text.
`useId()` generates any id used in an `aria-*` relationship.

## 3. Vue 3.5 — mandatory APIs

```ts
const input = useTemplateRef<HTMLInputElement>('input'); // not a matching-name ref()
const uid = useId(); // any generated id
defineModel<string>(); // every custom v-model
defineSlots<{ default(props: { row: Row }): unknown }>(); // scoped slots
```

Props destructure with defaults — **`withDefaults` is banned**. Passing a destructured prop as a
reactive source needs a getter: `watchEffect(() => consume(props.value))`.

Any watcher that starts a timer, a request or a subscription uses `onWatcherCleanup()` to cancel it.
Destroying an in-flight request is not optional when filters are debounced.

## 4. TypeScript

`strict: true`, `noEmit`. **Zero `any`** — no `any`, no `as any`, no implicit `any`, no `@ts-ignore`.
Use `unknown` plus a narrowing guard.

**TypeScript 6.0 is a bridge release, not a destination.** It is the last release built on the
JavaScript codebase; **7.0 is the native Go port**. 6.0 deprecates a long list of compiler options
and behaviours that become _hard removals_ in 7.0 (suppressible only with
`"ignoreDeprecations": "6.0"`). So: adopt no newly-deprecated option today, and keep `target`
conservative (`ES2022` here) rather than chasing the newest spec target — a 7.0 migration is a
separate task, not a side effect of upgrading `typescript`.

**Backend types are generated, never hand-written.** `php artisan typescript:transform` writes
`resources/js/generated/generated.d.ts` from the Spatie `Data` classes. Hand-writing an interface that
mirrors a `Data` class is how `any` and silent drift get in. Run it after any backend DTO or enum change.

Every page declares its layout with `defineOptions({ layout })`. State is explicitly typed.

## 5. Inertia 3

```ts
createInertiaApp({
  resolve: (name) => {
    const pages = import.meta.glob<PageModule>('./Pages/**/*.vue', { eager: true });
    return pages[`./Pages/${name}.vue`];
  },
  setup({ el, App, props, plugin }) {
    /* Pinia, Colada, PrimeVue, services */
  },
});
```

Navigation is `<Link>`. Optimistic updates are `router.optimistic(page => ({...}))` before the post.
Deferred props use `Inertia::defer(fn () => ...)` on the server and `deferred` props on the page.
`useHttp()` is available from `@inertiajs/vue3` for plain JSON calls that are not page visits.

**v3 breaking changes** (v3.0.0 is GA — see the official upgrade guide):

- Axios is **no longer a required dependency** — Inertia ships its own XHR client. Only install Axios
  as a peer dep if you genuinely need interceptors, and then wire it via `axiosAdapter` from
  `@inertiajs/core`.
- `qs` and `lodash-es` are no longer bundled. `qs` must be installed directly if you import it.
- `Inertia::lazy()` was **removed** → use `Inertia::optional()`. `Inertia::optional()`,
  `Inertia::defer()` and `Inertia::merge()` all still exist, and now also work inside nested arrays
  with dot-notation for partial reloads.
- `router.cancel()` was **removed** → `router.cancelAll()`, which takes granular per-type control.
  `cancelAll()` is the current API, not a removed one.
- The v2 `future` block is gone from `createInertiaApp` — all v2 future flags are always on.
- **ESM-only.** CommonJS `require()` no longer works, and **Node ≥ 24** is required.

Also in v3 and worth knowing: the default layout is set in `createInertiaApp` (plus a layout-props
API) instead of on every page; `resolve(name, page)` receives the full page object as a second
argument; `useDataElementForInitialPage` was renamed `useDataAttributeForInitialPage`;
`hideProgress()` / `revealProgress()` were removed; `preserveErrors` keeps validation errors across
partial reloads; instant visits are available.

**SSR is off** (`INERTIA_SSR_ENABLED=false`). There is no `bootstrap/ssr/` bundle. Enabling the config
without the bundle throws on the first render.

## 6. PrimeVue 5 — unstyled

```ts
.use(PrimeVue, {
    unstyled: true,
    ripple: false,
    license: import.meta.env.VITE_PRIMEUI_LICENSE,   // required, see below
    form: { resolver: zodResolver },
})
.use(ToastService)
.use(ConfirmationService)
.directive('tooltip', Tooltip)
```

**`license` is mandatory.** Without it v5 logs `[PrimeUI] PrimeUI license is not configured.` and
renders a banner. The **Community** key is free (primeui.dev/licenses/community). The key is not
sensitive — it may appear in the bundle — so `VITE_PRIMEUI_LICENSE` in `.env` is correct.

`unstyled: true` means **no theme package at all**. `@primevue/themes` was removed in v5; styled mode
would need `@primeuix/themes`. Do not install either in an unstyled project.

**v5 introduces NO breaking changes to the public component APIs** (official migration guide, v5.0).
What it does is **deprecate** a set of properties and components, removed in v6. Writing new code
against a deprecated API is the failure to avoid — it compiles today and dies at the next major.

| Deprecated in v5                                    | Use instead                                                       |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| `Button` `label` / `icon` / `iconPos` / `iconClass` | compose icon + text inside the default slot                       |
| `Button` `loading` / `loadingIcon`                  | own spinner in the default slot, toggle `disabled`                |
| `Button` `badge` / `badgeClass` / `badgeSeverity`   | a `<Badge>` child inside the default slot (**Button**, not Badge) |
| `InputMask` (component)                             | the `InputMask` **directive**                                     |
| `AutoComplete` `multiple`                           | `InputTags` (with typeahead)                                      |
| `MultiSelect` `multiple`                            | `Select` with `multiple`                                          |
| `ScrollPanel`                                       | `ScrollArea`                                                      |
| `Password`                                          | `InputPassword`                                                   |
| `ColorPicker`                                       | `InputColor`                                                      |
| `PanelMenu`                                         | `Menu` with `toggleable`                                          |
| `Image` / `Galleria`                                | `Gallery`                                                         |
| `ImageCompare`                                      | `Compare`                                                         |
| `Tabs` `scrollable`                                 | scrolling is the default behaviour                                |
| `Chart`                                             | PrimeUI PRO Charts — **commercial**, removed in v6                |

Also in v5: `UniqueComponentId` removed → `uuid` from `@primeuix/utils`; global config `inputStyle` →
`inputVariant`; `Tree` and `Menu` slot names changed; sizes are in `rem` against a 16px root.

**Do not depend on PRO components.** Chart and Editor are PrimeUI PRO (commercial licence) and are
removed in v6. This project uses `chart.js` directly — never install a PRO package.

> **⚠️ Context7 is NOT authoritative for PrimeVue.** The indexed PrimeVue docs are **v4** — they show
> `<Button label icon badge>`, `import InputMask from 'primevue/inputmask'` and
> `<AutoComplete multiple>`, all of which are deprecated in v5, and they do not document the mandatory
> `license` option. For PrimeVue use **only** the v5 migration table
> (`primevue.org/migration/v5`) and the CHANGELOG. Context7 stays useful for Tailwind, Zod, Pinia
> and Inertia.

**The Volt catalogue** is 50 components (plus `utils.ts`) and grows when `volt-vue` adds one. Never
trust a hardcoded count — run `ls src/volt` before importing. Not in the CLI: `Column` (comes from
`primevue/column`), `AutoComplete`, `Tooltip` (directive), `ScrollPanel`, `InputGroup`, `IconField`.

## 7. Pinia Colada — all server state

```ts
const { data, isPending } = useQuery({
  key: () => ['users', filters.value],
  query: () => fetch(`/api/users?${params.value}`).then((r) => r.json()),
  staleTime: 30_000,
  gcTime: 300_000,
  placeholderData: (prev) => prev,
});
```

Every query declares **`staleTime` and `gcTime`**. Shared queries and mutations use `defineQuery` /
`defineMutation`. Mutating a key requires invalidating the matching list and detail keys. Optimistic
rollbacks are guarded — check the cache still holds what you wrote before reverting.

## 8. DataTable

`Datatable.vue` from `src/volt/`, plus `Column` imported from `primevue/column`.

```vue
<DataTable :value="rows" lazy paginator :rows="15" :totalRecords="total" @page="onPage">
  <Column field="name" header="Name" sortable />
</DataTable>
```

Server-side `:lazy` is the default and the only mode for lists. The table never sorts, filters or
paginates in the browser — its events update the reactive filters object the query key depends on.
Volt's DataTable is a reduced feature set: **no in-cell editing, no column filtering, no row grouping.**
If a screen needs those, it is not a Volt DataTable screen — build it explicitly.

Row actions expose **both** states (a restore icon on soft-deleted rows) and never rely on a single
glyph. Destructive confirmation uses `Dialog` + `ConfirmDialog` — never `window.confirm()`.

## 9. Filters

Search (debounced, with a minimum length) · status select · date range. Composed into one
`URLSearchParams` helper reused by both the query and the export endpoint, so a filtered export exports
exactly what is on screen. Validate `date_from <= date_to` before sending.

## 10. Toasts

`Toast` mounted once, in the layout. `useToast()` for the calls. One toast system — no second one.
Errors are `severity: 'error'` with a message the user can act on, not the exception text.

## 11. Forms

`@primevue/forms` + Zod v4, wired through the `zodResolver` above. Schemas live in
`Modules/{ctx}/schemas/` and export the schema plus a `z.infer<>` type. Never hand-roll validation in a
`submit` handler. Field-level errors render through the Volt `Message` component.

## 12. FullCalendar 7

**v7 removed the standalone plugin packages.** There is no `@fullcalendar/daygrid` — the views are
subpath exports of the Vue connector, and `temporal-polyfill` is a required peer.

```ts
import FullCalendar from '@fullcalendar/vue3';
import dayGridPlugin from '@fullcalendar/vue3/daygrid';
import timeGridPlugin from '@fullcalendar/vue3/timegrid';
import interactionPlugin from '@fullcalendar/vue3/interaction';
import timeGridPlugin, { type DateSelectArg } from '@fullcalendar/vue3/timegrid';
```

**Never install `framer-motion`** — it is React-only. The Vue package is `motion-v`.

v7 renamed a lot: `eventClassNames` → `eventClass`, `eventBackgroundColor`/`eventBorderColor` →
`eventColor`, `eventTextColor` → `eventContrastColor`; DayGrid `weekNumber` → `inlineWeekNumber` and
TimeGrid → `weekNumberHeader`; `allDay` → `allDayHeader` in TimeGrid. Resource views moved to the
separate premium `@fullcalendar/vue3-scheduler`.

The calendar is the one screen with genuinely different read and write profiles — a `Queries/` class
for the month grid, an action for the booking. See `backend-php/SKILL-ARCHITECTURE.md` §4.

## 13. Animation

Vue's native `<Transition>` and `<TransitionGroup>` are the default. **Volt overlays already animate**
(Dialog, Drawer, Toast, Message, Menu, Popover, Fieldset all define enter/leave classes in their `pt`) —
never re-wrap them.

`motion-v` is justified only for layout animations, gestures, scroll-linked work or stagger. Rules:

- Load it per route with `defineAsyncComponent` — it is ~125 kB raw / ~42 kB gzip.
- Never animate `background-color` or `font-size` — transition the token in CSS.
- Never exceed 0.4 s. Never scale past 1.04 on hover.
- The export is `AnimatePresence`, not `Presence`.
- Respect `prefers-reduced-motion`.

## 14. Security

The frontend is not a trust boundary. Every authorisation decision is re-checked on the server; hidden
UI is a courtesy, never a control. Never expose secrets, internal ids or raw error text. Sanitise any
rich text. `v-html` only with a sanitiser and a comment saying so. Lock down the CSP in
`config/csp.php` — no `unsafe-eval` in production.

**CSP and Volt need a nonce.** PrimeVue overlays (Dialog, Drawer, Popover, Menu, Toast) inject their
styles at runtime, and Vue SFC `<style>` blocks compile to inline `<style>` tags. `style-src 'self'
'unsafe-inline'` is the easy path and it is forbidden in production — use a per-request nonce instead
(OWASP §5, §15.5):

```blade
{{-- resources/views/app.blade.php --}}
{{-- Nonce wiring (single source: spatie/laravel-csp `csp-nonce` binding).
    `@cspNonce` prints it in Blade (there is NO `csp_nonce()` helper).
    `Shared\Infrastructure\Http\Middleware\SecurityHeaders` (prepended in
    bootstrap/app.php) syncs it into `@vite` tags per request AND emits the
    CSP/OWASP headers. Never re-bind `csp-nonce`, never call
    `Vite::useCspNonce()` with no args (random nonce ≠ header nonce). --}}
<script @cspNonce>
    /* FOUC-killer / inline bootstrap code */
</script>
@vite(['resources/css/app.css', 'resources/js/app.ts'])
```

If you cannot ship a nonce, the acceptable fallback is `style-src 'self' 'sha256-…'` with the hashes
extracted from the Vite manifest — **not** `'unsafe-inline'`. Document any deviation with a
`Justified-OWASP-Deviation:` note.

### Theme controller

`.dark` on `<html>` is the single source. The toggle writes it; nothing else may. Inline the read in
`app.blade.php` `<head>` **before** the stylesheet or the page flashes light on load:

```html
<script @cspNonce>
  const t = localStorage.getItem('theme');
  if (t === 'dark' || (!t && matchMedia('(prefers-color-scheme: dark)').matches))
    document.documentElement.classList.add('dark');
</script>
```

The canonical copy lives in `resources/views/app.blade.php` — `@cspNonce`, not
`csp_nonce()` (no such helper in spatie/laravel-csp v3).

Persist through the VueUse `useColorMode` store. Never `data-theme`, never `.light`, and never a
second persistence layer on top.

## 15. Checklist before merging a page

- [ ] `defineOptions({ layout })` and `<Head>` present
- [ ] No `any`, no `@ts-ignore`, types generated not hand-written
- [ ] Vue 3.5 APIs used (`useTemplateRef`, `defineModel`, `onWatcherCleanup`)
- [ ] Server state through Colada with `staleTime` + `gcTime`; no store mirroring
- [ ] DataTable is `:lazy`; the browser does not sort or paginate
- [ ] Destructive action confirmed via `Dialog`; both delete and restore shipped
- [ ] No hardcoded colours; no inline classes overriding a Volt `pt`
- [ ] Keyboard reachable, labelled, focus ring intact
- [ ] `npm run types:check` and `npm run format:check` clean
